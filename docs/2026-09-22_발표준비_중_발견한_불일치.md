## 2. 항목별 상세

### 1. 정렬 스케일은 SMPL 쪽에만 적용된다 [코드]

`align_smpl_to_trellis.py:92-97`
```python
t_lo, t_hi = world_bounds(trellis_meshes)
s_lo, s_hi = world_bounds([smpl])
scale = (t_hi.z - t_lo.z) / (s_hi.z - s_lo.z)
smpl.scale = (scale,) * 3
```
- 회전(L88), 이동(L108)도 `smpl` 객체에만 적용. TRELLIS 메쉬는 `world_bounds()` 인자로 측정만 됨.
- PROJECT_STATUS.md:172 `Scale 0.588 (TRELLIS 1.001/SMPL 1.702)` — 이 기록은 맞음. 다만 "무엇을 무엇에 맞추는가"가 문서에 없음.

**문서 수정**: "SMPL 메쉬를 TRELLIS 정규화 공간에 맞추는 배율. TRELLIS 메쉬는 불변."

### 2. 0.589 재현은 정렬 정확도의 근거가 아니다 [코드 + 추론]

- 값의 정체가 "TRELLIS 정규화 높이 ÷ WHAM 추정 신장"이므로, 인간형 대상이면 세대·개체가 바뀌어도 0.55~0.62 부근에 모이는 것이 정상.
- 보고서 18쪽 "세대가 바뀌어도 상수 유지 — 3회 연속 재현"은 사실이지만, 정렬이 정확하다는 증거로 쓰면 "정규화 때문에 당연한 것 아니냐"는 반론에 답할 수 없음.

**문서 수정**: 게이트 표에서 스케일의 역할을 "이상 탐지"로 명기. 벗어나는 경우 = 메쉬 잘림, 부유 지오메트리로 높이 부풀음, WHAM 체형 추정 이상. 정렬 정확도는 IoU와 웨이트 1차 수신률로 판단.

### 3. 작업 공간은 미터가 아니다 [코드]

- `transfer_weights.py:4` 독스트링 "기본 0.08m", `RUNBOOK.md:347` 동일 표기.
- 실제 모디파이어는 `rigged.blend`, 즉 TRELLIS 정규화 공간에서 동작(`transfer_weights.py:73-74`). 이 공간의 신장은 약 1.0.
- 미터 환산: 0.08 ≈ 신장의 8% ≈ 13.6cm (Claude Code 계산, 코드 근거 아님).

**문서 수정**: 모든 "0.08m" → "0.08 (정렬 공간 단위, 신장 ≈ 1.0 기준)". CONVENTIONS에 "S4 이후 좌표 공간 = TRELLIS 정규화 공간" 항목 추가.

### 4. 관절-메쉬 거리는 SMPL 메쉬 기준이다 [코드]

`create_smpl_armature.py:53-57, 139, 147`
```python
def calibrate_joints(joints_raw, smpl_obj):
    mesh = smpl_obj.data            # L53 — SMPL_body
    ...
    kd.insert(mw @ v.co, i)         # L57 — 정렬된 SMPL 월드 좌표
```
- `--smpl-name` 기본값 `SMPL_body`(L47). 이 스크립트는 TRELLIS 메쉬를 한 번도 참조하지 않음.
- 후보 회전 4종(L60-65)은 X축 0/+90/−90/180도이며 **관절 좌표**에 적용. OBJ 임포터가 넣었을 수 있는 축 변환을 판정하는 용도. 24개 관절의 최근접 거리 **평균**(L71-74)이 최소인 후보 채택. 0.2 초과 시 경고만(L76-77).
- 따라서 이 지표가 보장하는 것은 "관절 좌표의 축이 SMPL 메쉬와 맞는다"까지. **뼈가 TRELLIS 메쉬 안에 있는지는 보장하지 않음.** 그 부분은 정렬 IoU + 웨이트 1차 수신률이 간접 담당.
- 값 0.028은 정규화 단위(≈ 신장의 2.8%, 약 4.8cm). 보고서 18쪽 "해부학적 간격 수준"은 SMPL 몸 기준으로는 맞는 해석.

**문서 수정**: 지표 이름을 "관절-SMPL 메쉬 거리(축 보정 판정)"로. 게이트 표 설명 수정. **G2r 후보 추가**: 관절 → TRELLIS 메쉬 표면 최근접 거리(직접 지표, 현재 없음).

### 5. 동작은 상대 회전으로 적용된다 [코드]

- rest pose: `create_smpl_armature.py:145` `joints_raw = json.load(f)["posed"]` — 키프레임 자세가 뼈의 rest. T-Pose 아님.
- 적용: `apply_wham_pose.py:99, 108-114` — `Rg_f[i] @ Rg_ref[i].T`로 기준 프레임 회전을 상쇄, `Rw`(정렬 단계가 SMPL_body에 남긴 월드 회전, L84-91)로 켤레변환, 부모 상대(L113) → 본 rest 기저(L114). 루트 이동도 `scale * (Rw @ (trans[f] - trans[ref]))`(L119).
- 기준 프레임 `--frame` 기본값 3(L39-40).
- Unity: Generic 리그. `export_unity_fbx.py:80` 주석 "Humanoid로 두면 근육 변환에서 동작이 왜곡된다 (rest가 T포즈가 아니라서)".
- `global_orient`라는 이름은 레포에 없음. pose[0]이 루트(Pelvis, `SMPL_PARENTS[0] == -1`).

**문서 수정**: "WHAM pose를 그대로 적용" → "골격 간 변환 없이 적용. 구현은 키프레임(기준 프레임) 대비 상대 회전". RUNBOOK 5-5에 rest pose = 키프레임 자세, Generic 리그 사용, 기준 프레임 번호가 TRELLIS 키프레임과 같아야 함을 명기.

### 6. 평균 betas 경로는 죽어 있다 [코드]

`generate_smpl_mesh.py:72, 82-87, 97-102`
- 정렬 대상 자세 메쉬: `posed = trimesh.Trimesh(vertices=verts[f], ...)` — **WHAM이 계산해 둔 프레임 f 정점** 그대로. betas를 거치지 않음.
- `mean_betas = betas.mean(0)`(L82-84)는 `smpl_tpose.obj`와 `joints["tpose"]`에만 사용. 아마추어는 `"posed"`만 읽으므로(항목 5) 두 산출물은 S4·S7 어디서도 소비되지 않음(grep 0건).
- 결과: 현재 리그의 체형 = 키프레임 시점 WHAM 정점. 프레임 간 betas 흔들림이 있어도 평균으로 보정되지 않음.

**결정 필요** (둘 중 하나):
- (a) 평균 betas로 프레임 f 자세를 다시 생성해 본류에 연결 → G3 "betas 안정성" 판정과 짝이 맞음.
- (b) 죽은 경로 제거하고 문서에 "키프레임 시점 정점 사용"으로 명기.

**문서 수정(결정 전에도)**: 보고서 12쪽 표현 "betas와 pose로 SMPL 메쉬 생성"은 최종보고서에서 "WHAM이 출력한 키프레임 시점 SMPL 메쉬 사용"으로.

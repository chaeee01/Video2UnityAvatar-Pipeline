# 오케스트레이터 설계 (v1) — 초안

- 작성: 2026-09-29 · 상태: **승인됨, 구현 전** (구현 2026-09-30 예정)
- 대상: `scripts/orchestrate.py` (W5 수요일 구현 예정)
- 한 줄 요약: **이 설계는 RUNBOOK 의 코드화다.** 새 절차를 만들지 않고, 사람이 밟던
  순서와 확인 포인트를 그대로 자동 실행·자동 판정으로 옮긴다.

## 0. 기존 자산 위에 올린다

새로 만드는 것은 오케스트레이터 하나뿐이다. 아래는 이미 있고 검증된 것을 그대로 쓴다.

| 자산 | 내용 | 출처 |
|---|---|---|
| 게이트 3종 | `gate_s2.py` · `gate_g2.py` · `gate_g2r.py` | 9/14-15 구현, 오탐 시험 통과 |
| 게이트 규약 | 표준출력 한 줄 요약 + `--out` 아래 JSON + **종료 코드 PASS 0 / FAIL 1** | RUNBOOK 5.5 |
| 판정 JSON | `gate` · `version` · `name` · `verdict` · `reasons` · `warnings` · `metrics` · `thresholds` · `source` | RUNBOOK 5.5 |
| CLI 규약 | 출력은 `--out`, 샘플명은 `--name`, 키프레임은 `--frame`, 샘플명 기본값 금지 | CONVENTIONS 2 |
| 경로 규약 | `data/00_raw` … `07_unity`, 폴더 번호는 S번호와 독립 | CONVENTIONS 1 |
| 단계 절차 | 각 단계의 명령·인자·확인 포인트 | RUNBOOK 0-7 |

게이트가 **종료 코드로 분기 가능**하다는 점이 이 설계의 토대다. 오케스트레이터는 게이트의
판정 로직을 다시 구현하지 않고 프로세스를 돌린 뒤 종료 코드만 본다. 임계값이 바뀌어도
오케스트레이터는 그대로다.

## 1. 실행 모델 — 2단 구조

GPU 작업은 Pod, Blender 작업은 맥북이라 한 프로세스로 묶을 수 없다. **같은
`orchestrate.py` 를 양쪽에서 돌리고 `--resume` 으로 이어받는다.**

```
[Pod 구간]   G0 → S2 → (G1a) → S3 → G2 → S5 → 5-1        ← 9/29 승인 당시. 현행은 10절
                                              ↓  run 폴더를 맥북으로 회수
[맥북 구간]  5-2 → 5-3 → 5-4 → G2r → 5-5 → FBX export
                                              ↓
[수동]       Unity 반입 (v1 범위 밖)
```

```bash
# Pod
python scripts/orchestrate.py --video /workspace/data/00_raw/zombie_walker.mp4 \
                              --name zombie_walker
# 맥북 (run 폴더 회수 후)
python scripts/orchestrate.py --name zombie_walker --resume
```

입력은 `--video <경로> --name <샘플명>`. `--resume` 은 run 폴더를 읽어 완료된 단계를
건너뛰고 다음부터 시작한다(5절). 구간은 실행 환경에서 자동 판별하지 않고 **완료 마커가
가리키는 다음 단계**로 정한다 — 맥북에서 Pod 단계를 부르면 그 자리에서 멈추고 사유를 낸다.

**Unity 반입은 v1 에서 수동으로 남긴다.** Unity 에디터 조작은 CLI 로 감쌀 수 없고,
Generic 리그 설정·Material 연결·Animator 구성이 전부 GUI 작업이다.

## 2. 단계 정의표

환경은 `micromamba run -n <env>` 로 지정한다. 활성화 상태에 의존하지 않기 위해서다 —
오케스트레이터 자신이 어느 환경에서 돌든 각 단계는 제 환경에서 실행된다.

### Pod 구간

| # | 단계 | 환경 | 명령 | 산출물 | 후속 게이트 |
|---|---|---|---|---|---|
| 1 | G0 입력 검증 | (없음, ffprobe) | `ffprobe` 로 프레임·fps·해상도 실측 | `g0.json` | 자체 |
| 2 | S2 SAM2 | `sam2` | `run_sam2.py --video --out --point` | `masks/` · `<샘플>_masked.mp4` · `keyframes/` | **gate_s2** |
| 3 | G1a 키프레임 | — | *(S2 안에서 수행 — 3절 주석 참조)* **→ 10/8 개정: S5 뒤의 독립 단계 (10절)** | `keyframes/candidates.json` | 없음 |
| 4 | S3 TRELLIS.2 | `trellis2` | `run_trellis2.py --image --out` | `<샘플>.glb` · `textures/` · `params.json` | **gate_g2** |
| 5 | S5 WHAM | `wham` | `run_wham.sh <마스킹 클립>` | `wham_output.pkl` · `overlay.mp4` | *(G3 미구현)* |
| 6 | 5-1 SMPL 메쉬 | `wham` | `generate_smpl_mesh.py --pkl --frame` | `smpl_frame<N>.obj` · `joints_frame<N>.json` | 없음 |

### 맥북 구간 (Blender 4.5 LTS)

| # | 단계 | 명령 | 산출물 | 후속 게이트 |
|---|---|---|---|---|
| 7 | 5-2 정렬 | `align_smpl_to_trellis.py --trellis --smpl --out` | `aligned.blend` · `aligned_params.json` | *(G2r 입력 적재)* |
| 8 | 5-3 아마추어 | `create_smpl_armature.py --blend --joints --out` | `rigged.blend` | *(관절 거리 적재)* |
| 9 | 5-4 웨이트 전이 | `transfer_weights.py --blend --out` | `transferred.blend` | **gate_g2r** |
| 10 | 5-5 동작 베이킹 | `convert_wham_npz.py` → `apply_wham_pose.py --blend --npz --frame` | `animated.blend` | 없음 |
| 11 | FBX export | `export_unity_fbx.py --blend --out` | `zombie_wham.fbx` | 없음 |

**G2r 의 위치에 주의.** `gate_g2r.py` 는 `--params`(5-2 산출) 외에 `--joint-dist`(5-3 로그)와
`--fallback-pct`(5-4 로그)를 인자로 받는다. 즉 **5-4 이후에야 판정할 수 있다.** 오케스트레이터는
5-3·5-4 의 표준출력에서 두 수치를 파싱해 보관했다가 G2r 에 넘긴다.

> **최초 지시와 다르게 잡은 것 2건** — 코드 근거로 교정했고 승인됐다(8절):
> ① G2r 을 Pod 구간이 아니라 맥북 구간 끝(5-4 뒤)에 두었다.
> ② 5-1 을 맥북이 아니라 Pod 구간에 두었다.

## 3. 게이트 분기표

| 게이트 | FAIL 시 | 자동 재시도 | 상한 | 근거 |
|---|---|---|---|---|
| **G0** | **즉시 종료** + 사유 | 없음 | — | 입력이 조건 미달이면 파이프라인이 할 수 있는 일이 없다. 영상 재생성·재소싱은 파이프라인 **밖**의 일이다 |
| **S2** | 대안 좌표로 재시도 | **있음** | 제안 **3회** | listener 사례 — 층진 의상에서 좌표 하나가 속옷만 잡았다. 좌표를 옮기면 통과하는 경우가 실재한다(stalker 는 겉옷으로 옮겨 통과) |
| **G2** | seed 변경 후 S3 재생성 | **있음** | 제안 **2회** | stalker 사례 — 형상은 정상인데 metallic 열화로 불합격했다. 생성이 확률적이라 seed 를 바꾸면 달라진다 |
| **G2r** | **정지 + 진단** | **없음** | — | 스케일 이탈은 **이상 탐지 지표**다(9/22 재정의). 같은 입력을 다시 돌려도 같은 값이 나오므로 재시도가 의미 없다. 상류(메쉬 잘림·부유 지오메트리·체형 추정)를 사람이 봐야 한다 |

### S2 재시도 — 좌표 순차 탐색

첫 시도는 `--point` 가 주어지면 그 값, 없으면 프레임 중앙이다. 실패하면 아래 순서로 옮긴다.
좌표는 첫 프레임 크기 기준 비율로 잡아 해상도에 무관하게 한다.

| 시도 | 좌표 | 노리는 것 |
|---|---|---|
| 1 | 지정값 또는 중앙 (0.50, 0.50) | 기본 |
| 2 | (0.50, 0.38) 상단 | 몸통 위쪽 — 겉옷 |
| 3 | (0.50, 0.62) 하단 | 다리·바지 |
| 4 | (0.46, 0.45) / (0.54, 0.45) 좌우 | 정중앙이 배경인 경우 |

**3회 전부 FAIL 이면 사람 호출 지점으로 정지한다**(6절). listener 는 세 좌표 모두 부분
선택이었고 단일 포인트로는 답이 없음이 실증됐다 — 다중 포인트는 v1 범위 밖이다(7절).

### G2 재시도 — seed 변경

`run_trellis2.py --seed <n>` 이 이미 있다(기본 0). 실패 시 `--seed 1` → `--seed 2` 로 올린다.
**다른 파라미터는 건드리지 않는다** — 해상도(1024)와 `--force-dielectric` 은 CONVENTIONS 8 의
생성 표준이고, 게이트 불합격을 이유로 표준을 흔들면 샘플 간 비교가 깨진다.

2회로 잡은 이유는 비용이다. 1024 생성이 약 4-5분이고 seed 를 바꿔도 같은 실패가 반복되면
모델이 그 입력에서 일관되게 실패하는 것이라, 세 번째 시도의 기대값이 낮다.

## 4. 재시도 정책

- **상한은 단계별로 다르다** — S2 3회, G2 2회(모두 제안값). 전체 재시도 총량 상한은 두지
  않는다. 단계별 상한이 이미 상계를 만든다(최악 3+2=5회 추가 실행).
- **상한 도달은 실패가 아니라 정지다.** 오케스트레이터가 종료 코드 2(사람 개입 필요)로
  끝내고, run 폴더에 무엇을 시도했고 왜 막혔는지 남긴다.
- **시도 이력은 `attempts.json` 에 누적 기록한다.** 재시도의 근거를 나중에 읽을 수 있어야
  임계값·좌표 전략을 고칠 수 있다.

```json
{
  "stage": "S2",
  "attempts": [
    {"n": 1, "params": {"point": [640, 360]}, "verdict": "FAIL",
     "reasons": ["커버리지 3.00% < 7.0%"], "gate_json": "gates/s2_try1.json",
     "started": "2026-09-29T10:00:00", "elapsed_s": 554},
    {"n": 2, "params": {"point": [640, 274]}, "verdict": "PASS",
     "gate_json": "gates/s2_try2.json", "elapsed_s": 549}
  ]
}
```

실패한 시도의 산출물은 **지우지 않는다.** 게이트 시험지로 쓰이는 데이터이고 재생성에 비용이
든다 — 9/10 의 listener 1·2차가 `rm -rf` 로 사라져 시험을 만들지 못한 전례가 있다.

## 5. 재개(resume) 설계

### run 폴더 구조

```
/workspace/data/runs/run_zombie_walker_20260929_1430/
├── run.json                 실행 메타 — 입력·시작 시각·구간·현재 단계
├── attempts.json            시도 이력 (4절)
├── done/                    단계 완료 마커
│   ├── G0.done              내용: 완료 시각 · 산출물 경로 · 소요
│   ├── S2.done
│   └── S3.done
├── gates/                   게이트 판정 JSON 원본
│   ├── s2_try1.json
│   ├── s2_try2.json
│   └── g2_try1.json
└── logs/
    ├── S2.log
    └── S3.log
```

산출물 자체는 규약 경로(`data/02_sam2/<샘플>/` 등)에 그대로 쓴다. run 폴더는 **실행 기록만**
담는다 — 산출물을 run 폴더로 옮기면 기존 절차·게이트 인자 경로가 전부 깨진다.

### 재개 규칙

1. `--resume` 이면 `--name` 으로 최신 run 폴더를 찾는다(`--run <경로>` 로 명시도 가능).
2. `done/<단계>.done` 이 있으면 **건너뛴다.** 마커는 게이트 PASS 까지 끝난 뒤에만 쓴다 —
   단계는 돌았지만 게이트가 FAIL 이면 마커를 쓰지 않는다.
3. 마커가 없는 첫 단계부터 재개한다.
4. 산출물이 실제로 있는지도 확인한다. 마커는 있는데 산출물이 없으면(회수 누락 등) **정지하고
   사유를 낸다.** 조용히 다시 돌리지 않는다 — 어느 쪽이 맞는 상태인지 사람이 정해야 한다.

맥북 구간 시작 시 Pod 에서 run 폴더와 산출물을 회수해야 한다. 회수 목록은 RUNBOOK 7절과
같고, 오케스트레이터는 **필요한 입력이 있는지 먼저 확인하고 없으면 무엇을 가져와야 하는지
경로로 알려준다.**

## 6. 사람 개입 지점

v1 에는 두 곳이 있다. 둘 다 **정지 → 안내 → 재개** 형태다.

### ① S2 좌표 (자동 재시도 소진)

```
[정지] S2 게이트를 통과하지 못했습니다 (3회 시도)
  시도 1  point=(640,360)  커버리지 3.00%  FAIL
  시도 2  point=(640,274)  커버리지 6.04%  FAIL
  시도 3  point=(640,446)  커버리지 0.81%  FAIL

  첫 프레임: /workspace/data/02_sam2/zombie_x/frame0.png
  이 그림을 열어 좀비 몸통의 픽셀 좌표를 찾은 뒤:

    python scripts/orchestrate.py --name zombie_x --resume --point <x>,<y>

  층진 의상(겉옷 안 속옷)이면 단일 포인트로는 어렵습니다 — listener 사례.
```

`--resume --point` 는 S2 마커가 없으므로 S2 부터 다시 시작하고, 주어진 좌표를 시도 4로
기록한다.

### ② Unity 반입 (v1 범위 밖)

FBX export 까지 끝나면 오케스트레이터가 종료하며 RUNBOOK 6절 절차를 출력한다 — Generic
리그 설정, Base Map 연결, Animator 구성. **Humanoid 로 두면 안 된다는 경고를 함께 낸다**
(rest 가 T포즈가 아니다).

### 알림 방식

v1 은 **표준출력 + 종료 코드**만 쓴다. 종료 코드는 `0` 정상 / `1` 오류 / `2` 사람 개입 필요로
나눈다. Slack·이메일 알림은 범위 밖이다 — 사람이 옆에서 돌리는 단계이고, 알림을 붙이려면
먼저 무인 실행이 되어야 한다.

## 8. 최초 지시와 다르게 잡은 것 — 3건 모두 승인됨

코드·문서 대조에서 나온 것이라 임의로 바꾸지 않고 확인을 거쳤다. **2026-09-29 3건 모두 채택** —
지시와 코드가 어긋날 때는 코드를 근거로 교정한다.

**① G2r 은 Pod 구간이 아니라 맥북 구간 끝에 둔다.**
지시는 Pod 구간을 `G0→S2→G1a→S3→G2→S5→G2r` 로 잡았다. 그런데 `gate_g2r.py:81-87` 이 받는
`--params` 는 `aligned_params.json`(5-2 정렬 산출물, 맥북)이고, `--joint-dist`·`--fallback-pct`
는 5-3·5-4 의 출력이다. Pod 구간에는 이 셋이 아직 없다. G2r 은 **5-4 뒤**가 유일하게 성립하는
자리다.

**② 5-1(SMPL 메쉬 생성)은 Pod 구간이다.**
지시는 맥북 구간을 "리깅 5-1~5-5" 로 잡았는데, RUNBOOK 5절은 "5-1 은 Pod(wham 환경),
5-2~5-5 는 맥북"이라고 적고 있고 `generate_smpl_mesh.py` 의 기본 경로도 `/workspace/...` 다.
5-1 은 WHAM pkl 을 읽어 SMPL 메쉬를 뽑는 단계라 wham 환경이 필요하다.

**③ G1a 는 독립 게이트가 아니다.** *(2026-10-08 에 뒤집혔다 — 10절. 아래는 9/29 당시의 판단이다.)*
구현된 게이트는 `gate_s2` · `gate_g2` · `gate_g2r` 셋뿐이다(`gate_g1a.py` 없음). 키프레임 선정은
`run_sam2.py` 안에서 점수 + 최소 간격으로 이뤄지고, **자세 항은 미구현**이다(실루엣 기반이
기각됐다 — ROADMAP W4). 따라서 v1 오케스트레이터에서 G1a 는 판정 지점이 아니라 **S2 의
산출물**이다. 후보 중 어느 것을 S3 에 넣을지는 현재 자동으로 1위를 쓰되, `candidates.json` 을
사람이 보고 바꿀 수 있게 `--keyframe <파일>` 로 덮어쓸 수 있게 한다.

## 10. 개정 — G1a 를 단계로 세우고 S5 를 S3 앞으로 (2026-10-08)

1절의 Pod 구간 순서와 8절 ③("G1a 는 독립 게이트가 아니다")을 뒤집는다. 위 본문은 9/29
승인본 그대로 두고, 바뀐 것만 여기 적는다.

```
[Pod 구간]   G0 → S2 → S5 → G1a → S3 → G2 → 5-1        (이전: G0 → S2 → (G1a) → S3 → G2 → S5 → 5-1)
```

**왜 바꿨나.** 9/30 E2E 에서 자동 선정이 고른 키프레임(f60 — 다리 붙음·얼굴 숙임)으로 만든
에셋이 불합격했다. 다리는 마스크로 잴 수 있지만 얼굴 방향은 잴 수 없고, 그 신호는 WHAM
pose 에 있다(시선 이탈각 f6 5.4° / f60 56.6°). 키프레임을 고르기 전에 S5 가 끝나 있어야 한다.

**세 안 중 2패스를 골랐다.** S2 는 지금처럼 마스크만으로 1차 후보를 내고(산출물이 그 자체로
완결이라 수동 실행·`--keyframe` 경로가 WHAM 없이 돈다), S5 뒤의 G1a 가 다시 매긴다.
- 경로 독립보다 **나쁜 입력 차단**이 우선이다 — 최종 에셋은 외형·동작이 모두 있어야 하므로
  "WHAM 실패 시 외형 생존" 의 가치는 제한적이다.
- 동작을 먼저 확정하면 장래 G3 재시도가 S3(약 430초)를 무효화하지 않는다. **G3 는 S5 와
  G1a 사이에 들어간다.**
- 기각: "S3 를 먼저 돌리고 얼굴 불합격 시 S3 재시도" — 불합격 때 430초를 다시 쓰고 판정이
  하류로 밀린다.
- 같은 Pod 에서 직렬로 도므로 **순서 변경의 벽시계 비용은 0** 이다.

**단계 정의 (2절 보충)**

| 단계 | 환경 | 스크립트 | 산출물 | 게이트 |
|---|---|---|---|---|
| G1a 키프레임 재선정 | wham | `select_keyframes.py` | `keyframes/key*_f*.png` · `candidates.json` · `_s2pick/` | 자체 (종료 코드) |

**분기 (3절 보충)**

| 결과 | 종료 코드 | 처리 |
|---|---|---|
| 재선정 완료 | 0 | S3 로 |
| 다리 벌린 프레임 없음 + 동작이 다리를 움직임 | **2** | 정지·인계. `--force-keyframe` 으로 강행, `--keyframe` 으로 직접 지정 |
| pkl 없음 · 트랙 0개 · frame_ids 불일치 | 1 | 실패. 상류(S2 마스크·S5)를 본다 |

**사람 개입 지점 (6절 보충) — ③ G1a 인계.** 자동 재시도가 없다. 다리가 벌어진 프레임은
영상에 있거나 없거나이고, 없으면 같은 영상으로는 고칠 수 없다. 권고는 영상 재생성이다.
다리가 움직이지 않는 동작이면(다리 4관절 범위 15° 미만) 인계하지 않고 진행한다.

**`--keyframe` 을 주면 G1a 를 건너뛴다.** 프레임 번호는 파일명(`_f<번호>`)에서 읽는다 —
5-1·5-5 가 같은 프레임의 SMPL 메쉬를 써야 하므로 추측하지 않고, 못 읽으면 실패한다.

**함께 고친 것 3건**
- 키프레임을 `key1_f*.png` 이름순 첫 장이 아니라 **`candidates.json` 의 1위**로 집는다. S2
  재시도마다 key1 이 쌓여(char_shuffle 에 4장) 1위가 아닌 것을 집을 수 있었다.
- run 기록을 `--until` 정지보다 먼저 쓴다. 반대였을 때는 `--until` 로 멈춘 run 을 이어받으면
  키프레임·프레임 번호가 남아 있지 않았다.
- S5 는 **트랙 수 ≥ 1** 을 확인한다(`run_wham.sh`). WHAM 은 사람을 못 잡아도 빈 pkl 과 종료
  코드 0 을 낸다 — 5절 규칙 4("산출물이 있어야 완료")가 파일 존재만 보아 뚫린 자리다.
